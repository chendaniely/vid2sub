# vid2sub: kickoff Q&A

Dan's answers to the questions asked while adopting plan-driven-development (skill 65072f9) in
this repo, which predates the skill. M1 was built and merged (#2) before it. Each item gives the
scenario as asked, the options, and the answer with Dan's reason in his own words; where he gave
none, it says so.

## Setup

### 1. Size (2026-10-23)

**Scenario:** vid2sub still has M2 (the editor), M3 (adding, reviewing, every platform) and M4
(Pages and releases) to build, and it handles API keys, a tunnel to the Spark and a local web
server. What do you expect kickoff to set it up as?

- **A. Large, in phases** (recommended): each remaining milestone a phase with its own plan,
  branch, PR, councils and retro.
- **B. Small, no phases:** one plan for everything left; doesn't fit, since vid2sub touches
  secrets and the network.
- **C. Large, finer phases:** phases smaller than milestones.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.
**Recorded as:** `**Size:** large` in `AGENTS.md`.

### 2. Visibility (2026-10-23)

**Scenario:** someone finds github.com/chendaniely/vid2sub, which is public today, with the Pages
editor and the install index planned at chendaniely.github.io/vid2sub/. What do you expect?

- **A. Public** (recommended): stays as it is; adds the [Dan] GitHub settings checklist.
- **B. Private:** the docs read on GitHub, nothing deployed; the Pages editor and index rethought.
- **C. Private until M4:** public when the Pages editor and the first release ship.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.
**Recorded as:** `**Visibility:** public` in `AGENTS.md`.

### 3. Demo (2026-10-23)

**Scenario:** someone opens chendaniely.github.io/vid2sub/ after M4 ships. What do you expect them
to find, and where do the project's docs live?

- **A. Live demo, docs on GitHub** (recommended): the Pages editor is the site and links to the
  docs; the docs are markdown read on GitHub, with diagrams in `docs/architecture.md`. Until M4
  the site stays GitHub's build of the README.
- **B. No demo, Quarto docs:** a Quarto site in `website/` on Pages, colliding with the editor's
  URL.
- **C. Demo inside a Quarto site:** the docs and the Shinylive editor in one Quarto site, changing
  spec §23.3.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.
**Recorded as:** `**Demo:** the Pages editor (M4)` in `AGENTS.md`; the docs case "public, with a
live demo": no `docs` target, diagrams in `docs/architecture.md`.

### 4. Where the repo lives (2026-10-23)

**Scenario:** a phase finishes and its branch is ready for review. Where do you expect it to go?

- **A. GitHub, as now** (recommended): phase PRs, CI and Pages on github.com/chendaniely/vid2sub;

- **B. Local only for now:** no PRs and no CI; the local checks are the gate.
- **C. Self-hosted remote:** loses GitHub Actions and Pages, which the spec relies on.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.

### 5. Mode (2026-10-23)

**Scenario:** midway through M2, a task finds that building it right would change one of your

**Recorded as:** `**Mode:** attended` in `AGENTS.md`.

## Adopting the workflow in a built repo

### 6. Phase names (2026-10-23)

**Scenario:** an agent resumes next month, reads `Plan: … Task 4` in a commit, and opens the
spec's §25, which talks about M1–M4. What do you expect the phase names to be?

- **A. M1 = Phase 1, M2 = Phase 2** (recommended): M1 is Phase 1, merged (#2); M2–M4 are Phases
  2–4 on `phase-2` onwards, with plans such as
  `docs/superpowers/plans/2026-10-23-vid2sub-phase-2.md`.
- **B. Start again at Phase 1:** M2 becomes Phase 1; off by one from the spec everywhere.
- **C. Keep M-names:** branches `m2` to `m4` and plans named `-m2.md`; departs from the skill's
  `phase-N` names.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.

- **B. A short Phase 1 end now:** the exit test and a retro of M1 before Phase 2 is planned.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.

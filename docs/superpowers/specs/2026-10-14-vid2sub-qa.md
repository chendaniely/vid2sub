# vid2sub: kickoff Q&A

Dan's answers to the questions asked while adopting plan-driven-development (skill 65072f9) in
this repo, which predates the skill. M1 was built and merged (#2) before it. Each item gives the
scenario as asked, the options, and the answer with Dan's reason in his own words; where he gave
none, it says so.

### 18. The kickoff council's Critical: the sidecar race (2026-10-24)

**Scenario:** in `vid2sub serve`, Dan presses Save just as a job on the Jobs page writes the
same episode's sidecar (or a CLI run does). The compare-and-swap leaves a window between its

- **A. Lock + re-check** (recommended): inside the app, one lock per sidecar, by its real path,
  around every write; the re-check moves to just before the rename, as §14.6 says, so a CLI run
  beside the app leaves only a sub-millisecond window, written into §18.3. Built in Phase 2 Task
  6, with a guard test that fails today.
- **B. Also a lock file** next to each sidecar that every writer takes: closes the window fully,
  but a crash holds Saves up for about 30 s, SMB's locking is unreliable, and §6.5 gains a file.
- **C. In-app lock only;** §18.3 says running both at once is not fully safe.

**Answer:** A. **Reason:** none given; Dan chose the recommended option.

### 33. Phase 2 Task 1: which model translates, with Gemma not loaded on the Spark (2026-10-30)

- **B. Qwen3.8 27B, Dan's coder:** the catalog's entry for Mandarin and Cantonese → English; it

**Answer:** C. **Reason:** none given. Gemma isn't required: translation takes any chat model
named in `vid2sub.toml`. Dan's config gains `spark-qwen36` (the catalog's `local-llm` slot, so
